事务要解决的问题是：一组操作要么全成功，要么全失败，中间状态不能被别人看到。

## 一句话总结

ACID 里的 I（隔离性）是性能与正确性的调节旋钮，隔离级别越高越不容易出错，并发能力越差。

## 核心内容

- 原子性（A）：要么全做完，要么全回滚
- 一致性（C）：约束在事务前后都成立
- 隔离性（I）：并发事务之间互不干扰
- 持久性（D）：提交了就不会丢

四种隔离级别，从松到紧：

1. 读未提交：能读到别人还没提交的数据（脏读）
2. 读已提交：只读已提交的数据，但同一事务里两次读结果可能不同（不可重复读）
3. 可重复读：同一事务里读到的数据保持一致（InnoDB 默认），可能出现幻读
4. 串行化：完全排队执行，最安全也最慢

## 例子

```sql
begin;
update accounts set balance = balance - 100 where id = 1;
update accounts set balance = balance + 100 where id = 2;
commit;   -- 两步都成功，或者 rollback 全部撤销
```

并发出问题的经典场景：两个人同时读到余额 100，各扣 60，最后余额不是 -20 而是 40——因为后写的覆盖了前写的。加锁（`select ... for update`）或改用原子更新能避免。

## 我踩过的坑

- 把事务开得太大（中间还调外部接口），导致锁长期不释放
- 忘了 `commit`，连接池里的连接一直挂着事务，排查了半天
- 以为「可重复读」就等于没有并发问题，实际仍要处理写覆盖
